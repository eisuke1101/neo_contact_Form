# NEO 総合依頼フォーム

1つのURLで「作業依頼」「不具合報告」「新規開発・仕様変更」の3種類を受け付けるフォーム。画面上部のタブで切り替える。
公開URL：https://script.google.com/macros/s/AKfycbyNacPk9zU8GVcuscaF7Y47QM7vjHUJfr5GzSRAHNOtoleH5sEY9zq-O_2B935uMx1a/exec

ほかに「PC等の不具合」「マテリアル関連」の小さいタブがあり、PC不具合フォームへのリンクとテクニカルサポートの電話番号を表示する（受付はしない）。

- 初期表示のタブは URL の `?type=work`（既定）/ `bug` / `dev` / `pc` / `material` で指定できる
- 既存の自動入力パラメータ（`person`, `email`, `phone`, `schoolDeptId`, `schoolDept`, `dueDate`）は従来どおり使える
- 氏名とメールアドレスは、タブ間で入力内容が同期される

## ファイル構成（Apps Script プロジェクトに配置する名前）

| ファイル | 内容 |
|---|---|
| `Code.gs` | 設定、画面表示（doGet）、送信後の処理キュー、共通の関数 |
| `work.gs` | 作業依頼の送信処理（既存の `submit` を移したもの） |
| `dev.gs` | 新規開発・仕様変更の送信処理 `submitDev` |
| `bug.gs` | 不具合報告の送信処理 `submitBug` |
| `index.html` | 画面の共通部分（ヘッダー、サポート時間、タブ、PC等の不具合・マテリアル関連の案内、モーダル、共通スクリプト） |
| `form_work.html` / `form_dev.html` / `form_bug.html` | 各タブの入力欄とそのスクリプト |

`_orig_*.gs/html` は改修前のファイル（比較用）。Apps Script には入れない。

## 書き込み先

| 種類 | スプレッドシート / シート | 番号 | 書き込む列 |
|---|---|---|---|
| 作業依頼 | 既存の「フォーム回答」 | `NEO-行番号` | 従来どおり |
| 新規開発・仕様変更 | 【リスト】システム開発依頼一覧 / 小規模案件 | `DEV-管理No.` | A〜F（管理No.、部署、担当、日付、詳細、資料）。G〜J は空欄 |
| 不具合報告 | NEO V2 UAT フィードバック管理表 / フィードバック一覧 | `BUG-ID` | A〜Q（B=新規 / New、C=N/A、D=Bug または CR、P・Q は空欄）。R列以降は書き込まない |

- 管理No. と ID は「その列の最大値＋1」で、ロックをかけた状態で採番する
- 添付ファイルの保存先
  - 開発依頼：フォルダ `1mgH317-…`（小規模案件シート F列の見出しに記載のフォルダ）
  - 不具合報告：自動作成されるフォルダ「NEO-不具合報告-添付」
- 15MBを超えるファイルは、利用者が Drive などに置いてリンク欄に記入する。そのリンクも F列（開発依頼）/ M列（不具合報告）にまとめて記載される

## デプロイ手順（新規プロジェクト）

既存フォームとは別に、新しい Apps Script プロジェクトとして作る（URL は新しくなる）。作業依頼の書き込み先は、既存のスプレッドシート「フォーム回答」をそのまま使う。

1. nh.neo.support@gmail.com で、新しい Apps Script プロジェクトを作成する
2. 上の表のファイルを作成する（`.gs` 4ファイル、`.html` 4ファイル）
3. プロジェクトの設定で、タイムゾーンを `Asia/Tokyo` にする
4. エディタで `ping` を一度実行し、権限を承認する
5. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」でデプロイする（実行ユーザー・アクセス権は既存フォームと同じ設定にする）
6. 3つのタブからそれぞれテスト送信し、シートへの書き込み、添付リンク、控えメールを確認する（テスト行は後で削除する）
7. 移行期間中は、既存フォームに新フォームの URL への案内を表示する

補足：
- 本文プレビューのリンクには、このプロジェクトのデプロイ URL が自動で使われる（`Code.gs` の `BASE_WEBAPP_URL` が空欄の場合）
- 本文 HTML の保存フォルダ（`DRIVE_FOLDER_HTML_ID`）が空欄だと、新しいプロジェクトでは新しいフォルダが自動作成される。既存と同じフォルダを使う場合は、そのフォルダの ID を設定する
- 既存の行のプレビューリンクは、既存フォームの URL を指している。既存フォームのデプロイを削除すると、それらのリンクは開けなくなる

## 前提・未確認事項

- nh.neo.support@gmail.com が、開発依頼のシート、不具合報告のシート、開発依頼の資料フォルダの編集権限を持っていること
- 開発依頼の Chatwork 通知は、「J列（通知）が空欄の行を既存スクリプトが拾う」前提で、J列を空欄のまま書き込んでいる
- 不具合報告シートの既存スクリプト（フォーム回答の転記、X〜AA列の日時の自動入力）が、新しいフォームからの書き込みでどう動くかは未確認
- 不具合報告の書き込み先を別のシートに切り替える場合は、`Code.gs` の `BUG_SPREADSHEET_ID` / `BUG_SHEET_NAME` を変更する（新しいシートは同じ列構成であること）
